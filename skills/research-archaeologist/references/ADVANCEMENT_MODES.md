# Optional Research Advancement — Capabilities and Gates

The Skill is an autonomous **research collaborator** when invited, not an automatic truth engine. `CONSOLIDATE` should be reliable on its own; deeper modes are independently optional and may be combined. Choose tasks by expected research value and feasibility, not by number of generated files.

| Operation | When useful | Concrete deliverable | Do not confuse with... |
| --- | --- | --- | --- |
| `CONFIRM` | Important prior result, suspect formula | Source span, proof scope, countercheck receipt | Truth of source's wider scientific hypothesis |
| `CHALLENGE` | Conflicting evidence, surprising equivalence | Minimal counterexample, explicit non-entailment | An attack on a stronger claim invented by the auditor |
| `REPAIR` | Partially invalid theorem or algorithm | Weaker valid statement and added assumptions | Source-authored theorem if the repair is new |
| `SYNTHESIZE` | Multiple branches share a pattern | Typed cross-branch mapping, preservation obligations | Structural isomorphism from vocabulary similarity |
| `DEVELOP` | Missing step, untested mechanism | New agent derivation / falsifiable rival hypotheses | Empirically confirmed discovery |
| `EXPERIMENT` | Local mechanism can be discriminated | Protocol or executed evidence with negative controls | A test plan labelled as completed experiment |
| `META_AUDIT` | Migration, proof lineage, stale state | Identity conflicts and revision changes | Assuming latest file replaces all old evidence |
| `RECONSTRUCT` | New agent will inherit the corpus | Conditional derivation path with entry references | Original historical reasoning if newly reconstructed |

## Development loop (optional)

Select one high-value claim or residual. First establish exactly what the source asserts; then challenge its minimal conditions. Preserve any surviving result. Propose a bounded repair or explicit competing interpretation, derive only what follows, and use a discriminating test if authorized. Record an improvement receipt and stop once marginal evidential value falls below effort or available resources.

### Cases from the SMFT v4.4–v8.6 *process* (teaching summaries only)

1. **Necessary versus sufficient attribution:** a compiler attributed a stronger one-to-one condition than a source explicitly required; the counterexample might be correct but targeted the compiler's stronger formulation.
2. **Finite-step repair:** a first-order control improvement term omitted a quadratic cost; the corrected formula motivated a counterfactual control test.
3. **Detector to controller gap:** alarms fired, but a residual history update was missing; a claimed closed-loop intervention was not exercised as intended.
4. **Leakage in neural proxies:** apparent held-out cases had shared donor provenance, narrowing what causal claims the trials support.
5. **Null/negative control:** renaming ordinary gradient descent as a culturally-inspired flow produced no novel mechanism. Preserve negative findings.
6. **Origin versus conditional structure:** a structure may have provable consequences when implanted without any evidence that unassisted large-scale training spontaneously selects it. Stop uninformative synthetic origin tests and preserve the conjecture.

These are **historical design lessons**, not guaranteed effects of this public Skill or independent reproductions. No proprietary raw source materials are included here.

## Resource and safety gates

Do not run expensive/long-term compute or external APIs without authorization. Where the user asks for a conjectural direction only, deliver the hypothesis and test plan instead of pretending experiments were run. Never use private held-out answers as working context. A sophisticated research agent may use its native tools or devise ephemeral procedures, but the release itself prescribes no Python, CLI or fixed algorithm.
