# 22 — v6.1 Primary mathematics, lineage revision and active-view release notes

**Field notes from ACTUAL v6.1 work; not runnable SKILL.md.**

- **Original mathematic formulas require trivial unit/probe tests.** `SRC-0270` physical p.4 defines complex time but incorrectly equates `∂/∂ζ` with `∂τ+i∂T`. Plugging in `f(ζ)=ζ` falsifies it instantly. Correct standard Wirtinger expression is `(∂τ−i∂T)/2`. It is easy for an index/summary to preserve the wrong formula because the model claims it is a definition. Recheck exact operator typing before permitting cross-domain propagation.
- **Hidden normalization assumption.** `SRC-0270` p.6 collapse normalization `Σ E=I` only implies probabilities sum to `||ψ||²`; p.57 appendix proof assumes `⟨ψ,ψ⟩=1` without writing it in the theorem. This is a narrow missing premise, not proof all measurement analogies are false.
- **Later original source can revise earlier philosophy, not merely elaborate vocabulary.** `SRC-0263` primitive recursive proto-time is explicitly critiqued by `SRC-0266` (recursive expression order may be representation, not ontological creation). `SRC-0265` then adds declaration/gates/ledger and distinguishes order from causality. Record `REVISED_BY` and type boundaries, not `PROVES`, and avoid guessing first-publication priority from tar metadata.
- **`TraceUpdate` does not imply tamper resistance.** In `SRC-0265` pp.45/52, a ledger transition is an operator definition, not a durability guarantee; append-only event semantics, protected authority, authenticated lineage and replay must be tested separately. Even an append-only log admits application-state reversal via compensating events.
